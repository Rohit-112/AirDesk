# AirDesk ✈️🖥️

AirDesk is a high-performance Android application designed for seamless cross-device communication. It allows users to synchronize their clipboards and transfer files directly between devices using WebRTC technology, all secured with end-to-end encryption.

## 🚀 Initial Goal
The project was born out of the need for a "Universal Clipboard" and a fast, server-less file sharing solution. Traditional methods often involve sending files to oneself on messaging apps or using cloud storage. AirDesk simplifies this by creating a direct, secure tunnel between two devices using a simple 6-digit session code or QR scan.

## ✨ Features

- **Real-time Clipboard Sync**: Copy text on one device and it instantly becomes available on the other. All clipboard data is encrypted before being sent via Firebase.
- **P2P File Transfer (WebRTC)**: Transfer files of any size directly between devices without uploading them to a central server, ensuring maximum speed and privacy.
- **QR Code Connectivity**: Quickly pair devices by scanning a QR code generated by the host.
- **Secure by Design**: Uses AES encryption for clipboard data and WebRTC for secure peer-to-peer file tunnels.
- **Session Management**: Automated session cleanup after 15 minutes of inactivity to ensure security and resource efficiency.
- **Transfer History**: Keeps track of your recently shared texts and files locally on your device.

## 🛠️ Architecture & Tech Stack

The project follows **Clean Architecture** principles and is built using modern Android development tools:

- **Language**: Kotlin
- **Asynchronous Programming**: Coroutines & Flow
- **Dependency Injection**: Hilt
- **UI Architecture**: MVVM (Model-View-ViewModel)
- **Networking/Signaling**: Firebase Realtime Database
- **Peer-to-Peer**: WebRTC (Google WebRTC Android SDK)
- **Local Database**: Room (for History)
- **Security**: Google Tink for encryption
- **Navigation**: Jetpack Navigation Component

## 📂 Project Structure

- `data/`: Implementation of repositories and data sources (Firebase, WebRTC, Room).
- `domain/`: Business logic, UseCases, and Repository interfaces.
- `viewmodel/`: UI Logic and state management.
- `fragment/`: UI screens (Home, Activity, Settings).
- `utils/`: Helpers for Encryption, QR codes, Networking, and File handling.

## 🔄 How it Works (Under the hood)

1. **Session Establishment**: The Host creates a session in Firebase, generating a unique 6-digit code.
2. **Signaling**: When a Guest joins, Firebase acts as a "Signaling Server" to exchange WebRTC SDP (Session Description Protocol) and ICE candidates.
3. **P2P Connection**: Once signaling is complete, a direct WebRTC Data Channel is opened between the devices. Firebase is no longer used for file data.
4. **Data Transfer**:
   - **Text**: Encrypted and sent through Firebase for persistent real-time sync.
   - **Files**: Chunked and sent through the WebRTC Data Channel for high-speed transfer.
5. **Security**: All text data is encrypted using a secret key before it leaves the device.

## 🛠️ Setup & Installation

1. Clone the repository.
2. Add your `google-services.json` to the `app/` directory.
3. Sync Gradle and run the app.
